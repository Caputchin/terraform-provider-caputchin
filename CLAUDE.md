# terraform-provider-caputchin

Workspace-scoped conventions. Non-negotiables (caveman style, commit rules, QA gate, teammate rules) live in [`../CLAUDE.md`](../CLAUDE.md) — that file governs this workspace too.

This is the **only Go repo** in Caputchin per [ADR-0013](../docs/adr/0013-terraform-provider-in-go.md). The TypeScript-only norm has one carve-out: HashiCorp's Terraform plugin SDK is Go-only, and the registry signing pipeline targets Go binaries.

## Layout

| Path | Purpose |
|---|---|
| `main.go` | Provider entrypoint (`providerserver.Serve`) |
| `internal/provider/` | Provider + resource + data source implementations |
| `internal/provider/teams/` | `caputchin_team` resource and data source |
| `internal/provider/sites/` | `caputchin_site_key`, `caputchin_site_config`, `caputchin_site_stats` |
| `internal/provider/account/` | `caputchin_account` data source |
| `examples/` | HCL examples surfaced on the Terraform Registry page |
| `docs/` | Generated by `tfplugindocs` at release time |
| `templates/` | `tfplugindocs` source templates |
| `scripts/` | Local-dev helpers (acceptance-test bootstrap, etc.) |
| `.goreleaser.yml` | Release config — standard HashiCorp template |
| `terraform-registry-manifest.json` | Declares plugin protocol v6 |

## Local dev

| Need | Command |
|---|---|
| Install / sync deps | `go mod tidy` |
| Unit tests (no live API) | `make test` |
| Acceptance tests (live API) | `make testacc` — requires `TF_ACC=1`, `CAPUTCHIN_MANAGEMENT_TOKEN`, `CAPUTCHIN_ENDPOINT`. See `scripts/testacc-bootstrap.sh` |
| Lint | `make lint` (`golangci-lint run`) |
| Generate docs | `make docs` (`tfplugindocs generate`) |
| Build binary | `make build` |
| Release dry-run | `make release-snapshot` |

Acceptance tests target a local `caputchin-platform` worker booted via `mprocs` — see [`../docs/guides/local-dev.md`](../docs/guides/local-dev.md). The provider points at `http://localhost:8787` via the `CAPUTCHIN_ENDPOINT` env var.

## Public HCL surface — naming discipline

Cap is an internal implementation detail of the Caputchin platform. The public HCL surface **never** uses the word `cap` in any resource, attribute, or example. The `/sites/{id}/cap-config` endpoint maps to the `caputchin_site_config` resource. Attribute names mirror the canonical management API field names, never the internal Cap-side knobs.

## Release flow

| Step | Action |
|---|---|
| 1 | Lead implements + QA-engineer reviews per phase (no self-review) |
| 2 | All phases QA-approved, acceptance tests pass locally vs `wrangler dev` |
| 3 | Tag `vX.Y.Z` and push — triggers `release.yml` → GoReleaser → Terraform Registry webhook ingest |
| 4 | File OpenTofu Registry metadata PR against `opentofu/registry` (manual at v0.1; automated later) |

Per ADR-0013 consequences: **publishing is irreversible**. The Registry namespace cannot be reclaimed.

## Versioning

[Semver](https://semver.org/) per the root [CLAUDE.md](../CLAUDE.md). Pre-1.0 (`v0.x`) is the dogfooding window — schema breaking changes allowed without major bump. After `v1.0.0`, schema changes follow semver strictly.
